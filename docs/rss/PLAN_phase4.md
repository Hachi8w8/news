# Phase 4: 重複排除

## 目標

同じ記事を二重に通知しないよう、処理済みURLをキャッシュファイルで管理する。

**完了条件**:
- 処理済みURLをファイルに保存・読み込みできる
- 既に処理した記事をスキップできる
- 30日以上古いURLがキャッシュから自動削除される
- キャッシュファイルがない初回起動でも正常に動作する

---

## 追加するファイル

```
src/
└── cache_manager.py   ← 新規追加

.cache/
└── processed_urls.json   ← 実行時に自動生成される
```

`main.py` も更新して、キャッシュとの照合処理を組み込む。

---

## キャッシュファイルの構造

`.cache/processed_urls.json` に処理済みURLと処理日時を記録する。

```json
{
  "articles": [
    {
      "url": "https://zenn.dev/example/articles/abc123",
      "processed_at": "2026-02-11T22:30:15Z"
    }
  ]
}
```

---

## 各ファイルの役割と留意点

### `src/cache_manager.py`

**役割**: キャッシュファイルの読み書きと、重複チェックを担うモジュール。

**処理内容**:

1. **キャッシュの読み込み**
   - 起動時に `.cache/processed_urls.json` を読み込む
   - ファイルが存在しない場合（初回起動）は空のキャッシュとして扱い、エラーにしない
   - JSONのパースに失敗した場合も空のキャッシュとして扱う（壊れたファイルで止まらないように）

2. **重複チェック**
   - RSS収集で取得した記事URLと、キャッシュ内のURLを照合する
   - URLは正規化済みのものを使う（Phase 1 で実装済み）
   - 未処理の記事のみを後続フェーズ（スクレイピング・AI処理）に渡す

3. **キャッシュの保存**
   - 全記事の処理が完了した後に、新しく処理した記事のURLと処理日時を追記する
   - 処理中断（エラー）で保存前に終了した場合、次回また同じ記事を処理してしまうが許容する（二重通知より取りこぼしを避ける設計）

4. **古いURLの自動削除**
   - キャッシュ保存時に30日以上前の `processed_at` を持つURLを削除する
   - キャッシュが無制限に膨らむのを防ぐため

**留意点**:
- `.cache/` ディレクトリが存在しない場合は自動で作成する
- キャッシュファイルへの書き込みは、処理が全件完了してから一括で行う（途中で書くと中断時に不整合が起きるリスクがある）
- GitHub Actions上では次のフェーズ（Phase 6）でキャッシュの復元・保存を担うが、このモジュール自体はローカルファイルの読み書きだけを担当する。GitHub Actionsとの連携はワークフロー側で行う

---

### `src/main.py`（更新）

**変更内容**:

処理フローにキャッシュ照合を組み込む。

```
1. RSS収集（Phase 1）
2. キャッシュ読み込み → 未処理記事のみ抽出  ← 今回追加
3. 本文取得（Phase 2）
4. AI分類 + 要約（Phase 3）
5. キャッシュ保存（新規処理分を追記）        ← 今回追加
```

**留意点**:
- 未処理記事が0件の場合は後続の処理をスキップして終了する（スクレイピングもAI呼び出しも不要）
- スキップ件数・処理件数をログに出力する

## テスト実行

### 手順

1. `uv run python src/main.py` を実行する（初回）
2. `.cache/processed_urls.json` が生成されていることを確認する
3. もう一度 `uv run python src/main.py` を実行する（2回目）

### 期待される結果

- 初回: 通常通り記事が処理され、`.cache/processed_urls.json` が作成される
- 2回目: 全記事が「処理済み」と判定されてスキップされ、処理件数が0になる

### 動作確認のコツ

2回目の動作確認のためにキャッシュをリセットしたい場合は `.cache/processed_urls.json` を削除するだけでよい。
