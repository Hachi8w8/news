# Phase 1: 基本構造 + RSS収集

## 目標

プロジェクトの基本構造を作成し、RSSフィードから記事を取得してコンソールに表示する。

**完了条件**:
- ZennとQiitaのRSSから記事を取得できる
- 過去24時間以内の記事をフィルタリングできる
- 取得した記事をコンソールに表示できる

---

## 各ファイルの役割と留意点

### `pyproject.toml`

**必要なパッケージ**:
- `feedparser`: RSSパース用
- `python-dateutil`: 日時パース用
- `python-dotenv`: `.env` ファイルから環境変数を読み込む
- `pytest`（開発依存）: テスト実行用

**留意点**:
- `uv add feedparser python-dateutil python-dotenv` で追加すると `pyproject.toml` が自動更新される
- `uv add --dev pytest` で開発依存としてpytestを追加する（本番実行には含まれない）
- `uv.lock` も自動生成されるのでセットでコミットする（再現性のため）
- GitHub Actions上でも `uv sync` でインストールする

---

### `.gitignore`

**除外するもの**:
- `.env`（APIキー漏洩防止）
- `.cache/`（実行ごとに生成されるため不要）
- `__pycache__/`, `*.pyc`（Pythonビルドファイル）
- `.venv/`（uvが作成する仮想環境）

---

### `.env.example`

**役割**: `.env` に設定すべき環境変数の一覧をコメント付きで示すサンプルファイル。

**留意点**:
- 実際の値は書かない（`.example` はリポジトリにコミットする）
- Phase 1 ではAPIキーは不要だが、後続フェーズで追加する変数を先にコメントとして書いておく

---

### `src/config.py`

**役割**: 設定値を一箇所に集約するファイル。環境変数の読み込みもここで行う。

**含める設定値**:
- RSSフィードURL（ZennとQiita）
- 記事取得期間（過去何時間か）

**環境変数の読み込み**:
- ファイル冒頭で `from dotenv import load_dotenv` → `load_dotenv()` を呼び出す
- これにより `.env` ファイルの値が `os.environ` に読み込まれる
- Phase 1 では環境変数は不要だが、Phase 3 以降で API キーなどを使うためこの段階で仕組みを入れておく
- GitHub Actions 上では `.env` は存在しないが、シークレット経由で環境変数が設定されるため `load_dotenv()` は空振りするだけで問題ない

**留意点**:
- マジックナンバーをコードに直接書かないためにこのファイルに集める
- フィードURLや時間のしきい値を変更する際、ここだけ修正すれば済む構造にする

---

### `src/rss_collector.py`

**役割**: RSS収集ロジックを担うモジュール。

**処理内容**:

1. **フィード取得**
   - `config.py` に書かれた複数のRSSフィードURLをループで処理する
   - `feedparser` を使って各フィードを解析する

2. **日時フィルタリング**
   - 各記事の公開日時（または更新日時）を取得し、過去24時間以内の記事だけを残す
   - 日時フィールドがない記事は取りこぼし防止のため含める

3. **URL正規化**
   - 同じ記事でもクエリパラメータやフラグメント（`#`以降）が異なるURLになることがある
   - 重複排除の精度を上げるため、URLからそれらを除去した形式に統一する

4. **記事データの整形**
   - タイトル、URL（正規化済み）、概要、出典（Zenn or Qiita）を辞書形式で返す

**留意点**:
- `feedparser` のフィールド名はフィードの形式（RSS 2.0 / Atom）で異なることがある。`updated_parsed` がなければ `published_parsed` を使うなど、フォールバックを考慮する
- `feedparser` はHTTPエラー時にも例外を投げずに空のフィードを返すことがある。`feed.bozo` フラグや `feed.status` を確認してログに残す
- 日時はUTC基準で比較する（ローカルタイムとの混在に注意）

---

### `src/main.py`

**役割**: 処理の起点となるエントリーポイント。

**処理内容**:
1. RSS収集（`rss_collector.py` を呼び出す）
2. 取得した記事をコンソールに出力する（タイトル・URL・出典・概要の先頭100文字程度）

**留意点**:
- Phase 1はあくまで動作確認が目的なので、出力は簡素でよい
- 後続フェーズで処理を追加していくため、各処理をモジュールに分けた構造にしておく

---

## ログ方針

- `print` ではなく Python 標準の `logging` を使う
- ログレベル:
  - `INFO`: 処理の開始・完了、取得件数など
  - `WARNING`: 記事の日時が取得できなかったなど、継続可能な異常
  - `ERROR`: フィード取得失敗など

---

## テスト実行

### 手順

1. `uv sync` でパッケージをインストール（仮想環境は自動作成される）
2. `uv run python src/main.py` を実行する

### 期待される結果

- ZennとQiita両方の記事が取得される
- 各記事のタイトル・URL・出典・概要がコンソールに表示される
- 実行ログに取得件数が出る

### 記事が0件のとき

- 過去24時間以内に記事がない可能性がある
- `config.py` の取得期間を一時的に48〜72時間に変更して再確認する
