# Phase 2: 本文取得（スクレイピング）

## 目標

Phase 1で取得した記事URLから、`trafilatura` を使って記事の本文を取得する。

**完了条件**:
- 各記事URLから本文テキストを取得できる
- リクエスト間隔（5秒）を守って取得できる
- 取得失敗時も処理が止まらずに続行できる
- 取得結果（成功・失敗件数）がログに出る

---

src/

## 各ファイルの役割と留意点

### `src/scraper.py`

**役割**: 記事URLから本文テキストを抽出するモジュール。

**処理内容**:

1. **本文取得**
   - `trafilatura` を使って指定URLから本文テキストを抽出する
   - `trafilatura.fetch_url()` でHTMLを取得し、`trafilatura.extract()` でテキストを抽出する

2. **リクエスト間隔**
   - 1件ごとに5秒スリープしてサーバーへの負荷を抑える
   - robots.txt 上は Zenn・Qiita とも記事ページへのクロールは問題ない（設計書参照）

3. **成功・失敗の判定**
   - 抽出結果が100文字以上であれば成功とみなす
   - 100文字未満または `None` の場合は失敗扱いにする

4. **失敗時のフォールバック**
   - 取得失敗でも処理を止めない
   - `content = None` として記事データに含め、後続のフェーズ（AI分類）でタイトル + RSS概要で代替する

5. **複数記事の処理**
   - 記事リストをループして1件ずつ処理する
   - 処理件数・成功数・失敗数をログに出力する

**留意点**:
- `trafilatura` は JavaScript で動的に生成されるコンテンツには対応していない。ZennとQiitaは静的HTMLで本文が提供されているので問題ない
- `trafilatura.fetch_url()` はリダイレクトに自動対応するため、短縮URLなどへの対応は不要
- ネットワークエラーやタイムアウトは `trafilatura` 内部でハンドリングされ、例外を投げずに `None` を返す。追加の例外処理は不要だが、念のため `try/except` で囲む
- 本文が長すぎる場合（10,000文字超）は次フェーズ（AI分類）でトリミングするため、ここでは切り詰めない

### `src/main.py`（更新）

**追加する処理**:

2. 各記事の本文取得結果（成功/失敗）をコンソールに表示する

## 依存パッケージの追加

```bash
uv add trafilatura
```

---

## テスト実行

### 手順

1. `uv add trafilatura` でパッケージを追加
2. `uv run python src/main.py` を実行する

### 期待される結果

- 各記事URLにアクセスして本文が取得される
- 取得成功の記事は本文の先頭200文字程度がコンソールに表示される
- 取得失敗の記事は「本文取得失敗」などと表示される
- 全件処理後に成功・失敗の件数がログに出る
- 記事間に5秒の待機が入るため、全体の処理時間は 件数 × 5秒 程度かかる

### 処理時間の目安

- 記事20件の場合: 約100秒（1分40秒）
- 記事30件の場合: 約150秒（2分30秒）

テスト時は待つ必要があるので注意。
