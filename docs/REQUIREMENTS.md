# AI News Discord 通知システム - 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
AI News Discord 通知システム

### 1.2 目的
AI関連の最新情報を自動収集・分類・要約し、Discord経由で効率的に受け取れるようにする。

### 1.3 背景
- AI技術の進化が早く、重要な情報を見逃しやすい
- 複数の情報源（Zenn、Qiita、X/Twitter）を毎日チェックするのは時間がかかる
- 開発に役立つ情報と業界動向を区別して把握したい
- ノイズ（AI無関係の記事）を排除したい

---

## 2. ターゲットユーザー

### 2.1 主要ユーザー
- **AI/機械学習エンジニア**: 実装テクニックやツール情報を求める開発者
- **技術リーダー・CTO**: AI業界の動向や新技術の把握が必要な意思決定者
- **個人開発者**: 最新のAI技術をキャッチアップしたい学習者

### 2.2 利用シーン
- 朝の通勤時にDiscordで前日のAIニュースを確認
- 開発中に「こういうツールないかな」と思ったときに過去の通知を検索
- チームでAI技術の情報共有

---

## 3. 機能要件

### 3.1 情報収集（何を取ってくるか）

#### FR-1: RSS記事収集
- **対象**: Zenn、Qiita の RSS フィード
- **範囲**: 全ジャンル（トピック・タグ指定なし）
- **頻度**: 1日1回（JST 07:00）
- **期間**: 過去24時間以内の記事

#### FR-2: Xトレンド収集
- **対象**: X（Twitter）全体のAI関連トレンド
- **期間**: 過去24時間以内
- **頻度**: 1日1回（JST 07:00）

#### FR-3: Xアカウントウォッチ
- **対象**: 指定したアカウント（OpenAI、Anthropic、AI研究者など）の投稿
- **アカウント数**: 設定ファイルで管理（推奨7-10アカウント、上限なし）
- **期間**: 過去24時間以内
- **頻度**: 1日1回（JST 07:00）

---

### 3.2 RSS記事の処理（記事をどう処理するか）

#### FR-4: AI関連判定とカテゴリ分類
取得したRSS記事を以下の3つに自動分類：

- **開発向け（dev_ai）**: AIツール、API、実装テクニック、プロンプト手法
- **業界動向（industry）**: 新モデル発表、研究論文、規制動向、企業ニュース
- **AI無関係（not_ai）**: AI関連ではないが、技術記事として興味深い可能性のある記事

#### FR-5: 記事要約生成
- **dev_ai / industry**: 記事本文から2-3行の要約を生成（最大400文字）
- **not_ai**: タイトル+概要から簡易要約を生成（最大300文字）

---

### 3.3 X投稿の処理（投稿をどう処理するか）

#### FR-6: トレンド要約
- AI関連で盛り上がっている話題を5-10件ピックアップ
- 各話題ごとに要約と代表的なポストURLを提示
- 開発向け/業界動向のラベル付け

#### FR-7: アカウント投稿要約
- 指定アカウントのAI関連投稿を要約
- 投稿者名、内容要約、ポストURLを提示
- 有益な情報がない場合は「該当なし」を通知

---

### 3.4 重複排除

#### FR-8: 記事URL重複排除
- 一度処理した記事は再通知しない
- URLを正規化して比較（クエリパラメータ、フラグメントを無視）
- 処理履歴は30日間保持

#### FR-9: X投稿URL重複排除
- 一度通知した投稿は再通知しない
- 処理履歴は30日間保持

---

### 3.5 通知

#### FR-10: Discordチャンネル別通知
5つのチャンネルに情報を分類して通知：

| チャンネル | 内容 | 情報源 |
|-----------|------|--------|
| `#ai-dev-news` | 開発向けAI記事（要約） | Zenn/Qiita（dev_ai） |
| `#ai-industry` | AI業界ニュース（要約） | Zenn/Qiita（industry） |
| `#tech-other` | AI無関係の技術記事（要約） | Zenn/Qiita（not_ai） |
| `#ai-x-trend` | X全体のAIトレンド | X/Twitter（全体） |
| `#ai-x-watch` | 特定アカウントの注目投稿 | X/Twitter（指定アカウント） |

#### FR-11: 通知フォーマット
- Discord Embed形式で見やすく整形
- チャンネルごとに色分け（緑/青/グレー/紫/オレンジ）
- 記事タイトル、URL、要約、出典を明記
- 複数記事がある場合は1メッセージに最大10件まで含める

---

### 3.6 設定管理

#### FR-12: ウォッチアカウント管理
- ウォッチ対象のXアカウントを設定ファイル（`config.py`）で管理
- コード変更なしでアカウントの追加・削除が可能

## 4. 非機能要件

### 4.1 性能要件

#### NFR-1: 処理時間
- 全パイプライン（収集→分類→要約→通知）を **5分以内** に完了

#### NFR-2: 応答時間
- Discord通知が実行開始から **5分以内** に届く

### 4.2 コスト要件

#### NFR-3: 月額コスト上限
- **月額 $2（約300円）以内**
- 目標: $0.72 - $1.68/月（約110-260円/月）

#### NFR-4: 無料枠活用
- Gemini API: Free Tier（250リクエスト/日）で運用
- GitHub Actions: パブリックリポジトリで無料運用
- Discord Webhook: 無料
- xAI: $25無料クレジットを最大限活用（1.5-2.9年分）

### 4.3 可用性要件

#### NFR-5: 実行頻度
- 1日1回、**毎朝 JST 07:00** に確実に実行

#### NFR-6: 失敗時の対応
- 全体が失敗した場合、Discord に失敗通知を送信
- 部分的な失敗（一部記事の処理失敗など）は継続実行
- エラーはログに記録

#### NFR-7: メンテナンス性
- 手動実行機能（GitHub Actions UIから即座に実行可能）
- ローカル環境でのテスト実行に対応

### 4.4 拡張性要件

#### NFR-8: 情報源の追加
- 将来的に新しい情報源（はてブ、Reddit等）を追加可能な設計

#### NFR-9: 通知先の追加
- 将来的にSlack、LINE等の通知先を追加可能な設計

### 4.5 セキュリティ要件

#### NFR-10: API キー管理
- すべてのAPIキーは GitHub Secrets で管理
- コードやログにAPIキーを含めない

#### NFR-11: クロール配慮
- robots.txt を遵守
- 適切な間隔（5秒）でスクレイピング
- User-Agent を明示

## 5. 制約条件

### 5.1 技術制約

#### C-1: 使用言語
- Python 3.12 以上

#### C-2: 実行環境
- GitHub Actions（ubuntu-latest）

#### C-3: API制限
- **Gemini API Free Tier**:
  - 10 RPM（リクエスト/分）
  - 250 RPD（リクエスト/日）
  - 250,000 TPM（トークン/分）
- **xAI x_search**:
  - `allowed_x_handles` は最大10件/リクエスト
- **Discord Webhook**:
  - 30リクエスト/分
  - 1メッセージに最大10個のEmbed
  - Embed文字数制限（タイトル256字、説明4096字）

### 5.2 運用制約

#### C-4: 情報源の利用規約
- Zenn、Qiita の robots.txt を遵守
- X/Twitter の利用規約を遵守（xAI API経由でアクセス）

#### C-5: データ保持期間
- 処理済みURL履歴: 30日間
- それ以上のデータ保存は行わない（プライバシー配慮）

### 5.3 予算制約

#### C-6: 初期費用
- **$0** （すべて無料枠または無料クレジットで運用）

#### C-7: 運用費用
- **月額 $2 以内**（無料クレジット枯渇後）

## 9. リスクと対策

### リスク1: API制限超過
- **発生確率**: 低
- **影響度**: 中（一時的に通知が届かない）
- **対策**: 
  - バッチ処理とスリープで制限内に収める
  - リトライロジックで一時的なエラーを吸収

### リスク2: 情報源のrobots.txt変更
- **発生確率**: 低
- **影響度**: 高（スクレイピング不可）
- **対策**: 
  - 定期的にrobots.txtを確認
  - RSS概要のみでの要約にフォールバック

### リスク3: API仕様変更
- **発生確率**: 中
- **影響度**: 高（機能停止）
- **対策**: 
  - 公式ドキュメントを定期確認
  - エラー発生時のDiscord通知で早期検知

### リスク4: 無料クレジット枯渇
- **発生確率**: 高（1.5-2.9年後）
- **影響度**: 低（月額$1-2で継続可能）
- **対策**: 
  - 枯渇前にxAIデータ共有プログラム参加を検討
  - 必要に応じて代替LLMに切り替え
